# STATUS — Mirsad's website shield (`mirsad-gateway/`)

_Last update: 2026-11-25 (+04), at the merge into the Mirsad repository. Prototype for the hackathon submission._

## What is built and verified
- One `docker compose up -d --build` starts the engine (API and dashboard on :8000), the watcher and the gateway; the
  `demo` profile adds six simulated sites on a private network, the `sim` profile a phone simulator.
- Gateway: Tailscale exit node and mitmproxy addon; holds unknown sites, refuses or resets blocked ones, bilingual
  checking, warning and block pages over plain HTTP (and HTTPS in intercept mode), `shield.test` protection page,
  revocation and unblocking from engine events, fail closed after 8 s.
- Engine: layers 0–4, the no-browser fetcher, static JavaScript analysis, cloaking comparison, fuzzy page hashes and
  change detection, URL and page models, 80 kinds of finding with English and Arabic titles, batch scoring of a CSV.
- Second-opinion review on every block, with the asymmetric fact-based policy; local LLM optional.
- Evidence pack with bilingual PDF / HTML report, captures, registration records, English and Arabic takedown texts and
  a SHA-256 manifest; one `SS-…` case reference everywhere.
- Watcher: Certificate Transparency, newly registered domains, look-alike sweep, helpline-number check, campaign
  linking.
- Dashboard in English and Arabic: Live, Reputation, Evidence, Campaigns, Benchmarks.

## How it was checked
- Test suite: 1,025 passed, 5 skipped on 25 Nov 2026 (as recorded in the README); at the merge, `pytest --collect-only`
  in this folder collects 1,030 tests. The suite was not re-run after the import.
- At the merge, the running engine (started from the team's working copy, not from this folder) reported every
  component `ok` on `/v1/health`, and `POST /v1/check` for `https://adpolice-fines-payment.com/` returned the README's
  verdict: BLOCK 91.2 at stage `page`, with the same six reasons and points.
- Demo: the six scenarios and the no-phone fallback, with expected output, are in `docs/DEMO.md`; intercept mode was
  verified through the simulator.
- Security review of 25 Nov (`docs/SECURITY_REVIEW.md`): fixed, mitigated and accepted findings; prompt injection
  unblocked 0 of 12 scam pages; no request reached the private canary.

## What is measured
All numbers are in `docs/BENCHMARKS.md` (generated by `ml/bench/report.py`), `docs/BENCHMARKS_PAGE.md`,
`docs/BENCHMARK_PROTOCOL.md` and `docs/BENCHMARKS_REVIEW.md`; the README section 9 copies the headline tables.

| What | Result |
|---|---|
| Official UAE URLs flagged by the served URL model | 0 of 15,669 (and 0 of 3,674 more) |
| Whole engine on legitimate UAE and fresh-feed URLs | 0 of 400 blocked, 3 warned |
| Served URL model, fresh 48-hour feed set | ROC-AUC 0.9914, recall 0.8775 at 1% FPR |
| Served page system, `pages_test` (15,048 pages) | precision 0.993, recall 0.820, FPR 0.61% |
| User's wait on a first visit, 95 live pages | 4.5 ms p50, 2.3 s p95 |
| Review, 56 final listing blocks | 43 of 43 scams kept blocked (rules and model) |
| Abu Dhabi listings, final scan of 8,883 websites | 56 blocked, 322 warned (development numbers) |

## What is not measured or not done
- End-to-end recall of the whole engine on a reserved set of live phishing URLs.
- The phone path over Tailscale on a physical phone (exercised with the simulator only).
- An independent test of the listings numbers: rules were tuned on the same list.
- Not connected to the other parts of Mirsad: no gateway output reaches the portal's API, and the portal's watchlist
  does not feed the gateway (README section 8).
- Open security items marked *needs owner* in `docs/SECURITY_REVIEW.md` (non-root engine image, per-service secrets,
  review fallback fetcher, ownership-source hardening, LLM judge's negative points).
- Not in the repository, by decision (README section 9): the datasets and their builders and manifests (`ml/data/`),
  the Phishpedia-derived global brand list (`src/scamshield/intel/data/global_brands.json`, optional: without it only
  the UAE registry is matched by name), the recorded page snapshots (`tests/pipeline/snapshots/`; their tests skip)
  and the per-URL rows of the benchmark results. The repository ships the UAE registry, the trained model files
  (except the GPU page encoder) and the results as counts and metrics.
